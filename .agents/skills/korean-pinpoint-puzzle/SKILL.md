# 한국어 Pinpoint 퍼즐

이 스킬은 한국어 사용자를 위한 매일 1문제형 Pinpoint 연상 퍼즐을 만들 때 사용한다. 목표는 쉬운 나열형 퀴즈가 아니라, 초반에는 여러 해석이 가능하고 후반으로 갈수록 하나의 정답으로 수렴하는 문제를 만드는 것이다.

## 필수 참조 문서

이 repo에서 문제 생성, 저장, 검증, 스코어링, 예약, 공개 작업을 할 때는 먼저 `docs/product-plan.md`, `docs/harness-architecture.md`, `docs/operations.md`, `references/harness-workflow.md`를 읽고 그 기준을 따른다. 문제 품질 자체를 판단하거나 새 문제를 만들 때는 추가로 `references/puzzle-rules.md`를 읽는다.

## 기본 산출 형식

문제는 다음 구조를 따른다.

```json
{
  "answer": "출입국",
  "aliases": ["출입국 심사", "입국심사", "출국심사"],
  "category": "사회/제도",
  "difficulty": 4,
  "clues": ["경계", "통과", "도장", "비자", "여권"],
  "rationale": "초반에는 공간적 이동으로 열어두고, 후반에는 여권/비자로 출입국으로 수렴한다."
}
```

## 난이도 기준

- 단서 1~2는 정답을 직접 가리키지 않고 여러 방향으로 해석 가능해야 한다.
- 단서 3은 의미 영역을 좁힌다.
- 단서 4는 강한 후보를 만든다.
- 단서 5는 정답을 거의 확정하게 만든다.
- 정답은 너무 넓은 상위 분류가 아니라 한 단계 구체적인 개념, 인물, 작품, 제도, 이론, 용어여야 한다.
- 단서에 정답 문자열이나 정답의 핵심 명사를 그대로 넣지 않는다.
- `한식`, `과일`, `한국의 강`, `영화감독`처럼 쉬운 나열형 카테고리는 피한다.

## 생성 절차

사용자가 "하네스를 돌려줘", "후보를 생성하고 검증해줘", "오늘 문제 후보 만들어줘"처럼 전체 파이프라인 실행을 요청하면 에이전트가 직접 후보 문제 JSON을 작성한 뒤 `references/harness-workflow.md`에 따라 `npm run puzzles:harness -- --input <파일> --dry-run`을 먼저 실행한다. 통과하면 저장 실행을 한다. 개별 단계 수정이나 디버깅이 필요할 때만 하위 CLI를 직접 실행한다.

1. 먼저 도메인을 다양하게 잡는다: 사회, 과학, 기술, 역사, 예술, 영화, 언어, 경제, 철학, 지리.
2. 정답을 먼저 정하고, 5번째 단서에서 역으로 1번째 단서까지 약하게 만든다.
3. 각 단서가 한 단어 또는 짧은 명사구가 되도록 다듬는다.
4. `aliases`에는 한국어 띄어쓰기, 한자어/외래어 표기, 흔한 축약 표현을 넣는다.
5. 문제마다 `rationale`에 단서가 어떻게 수렴하는지 짧게 설명한다.

## 저장 절차

1. 후보 문제를 임시 JSON 파일로 작성한다. 형식은 `{ "puzzles": [...] }` 또는 배열 `[...]` 둘 다 허용된다.
2. `npm run puzzles:harness -- --input <임시파일> --dry-run`을 실행한다.
3. 검증 또는 스코어링 이슈가 나오면 후보를 수정하고 다시 실행한다.
4. 통과하면 `npm run puzzles:harness -- --input <임시파일>`을 실행해 운영 후보 저장소에 넣는다.
5. 운영 데이터에 남길 필요가 없는 임시 파일은 삭제한다.

## 검토 절차

자세한 품질 기준은 `references/puzzle-rules.md`를 읽는다. 특히 다음 경우는 반려하거나 수정한다.

- 1번째 또는 2번째 단서만으로 정답이 너무 쉽게 보이는 경우
- 5번째 단서까지 봐도 정답이 여러 개 가능한 경우
- 단서가 단순 예시 나열에 그치는 경우
- 정답보다 더 자연스러운 대체 정답이 있는데 `aliases`에 없는 경우
- 사실관계 오류, 시대착오, 특정 집단에 대한 비하나 편견이 있는 경우
